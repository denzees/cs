2.1 Types and methods of data transmission

Data packets

Data sent over a network is split into small packets. Each packet can take a different route, which helps if a route is busy or broken. The only drawback is that the data must be reassembled at the destination.

PartContainsPurpose
HeaderIP address of sender and receiver, sequence number, packet sizeRouting and reassembly in the right order
PayloadThe actual dataWhat is being delivered
TrailerEnd-of-packet marker and CRC error checkSeparates packets and detects errors
CRC in the book’s method: the sender adds up the 1-bits in the payload and stores the total (as a hex value) in the trailer. The receiver repeats the calculation. If the totals match there is no error; otherwise the packet is re-sent.

Packet switching

  1. The message is split into packets, each with a header.
  2. Each router (node) reads the destination IP address and picks the best available route, which depends on how busy each node is.
  3. Packets may arrive out of order.
  4. The receiver uses the sequence numbers to reassemble the message.
BenefitsDrawbacks
No single line is tied up; faulty or busy routes can be avoided; easy to expand; high transmission ratePackets can be lost and re-sent; poor for real-time streaming (e.g. live sport); delay while packets are re-ordered

Hopping (extension): a hop number in the header drops by 1 at every router. At 0 the packet is deleted, so lost packets cannot clog the network, and the receiver asks for a re-send.

Universal serial bus (USB)

USB is serial transmission and the standard way to connect devices. The 4-wire cable has two wires for power (red +5 V, black ground) and two for data (white Data+, green Data−). It supports half-duplex and full-duplex.

BenefitsDrawbacks
Device detected automatically and driver loaded; plug fits only one way; industry standard; various speeds (1.5 Mbps to 5 Gbps); powers devices; re-sends on errors; easy to add hubs; backward compatibleStandard cable limit about 5 m (hubs extend it); early USB versions may not be supported; slower than Ethernet for large transfers

USB-C: small, 24-pin, reversible connector. Up to 100 W power and 10 Gbps data (supports 4K video). Backward compatible with an adaptor.

2.2 Methods of error detection

Errors can occur from interference on cables, problems during packet switching (data lost or even gained) and skewing in parallel transmission. A corrupted message is meaningless to a computer, so errors must be detected.

MethodHow it worksWeakness
Parity checkCount the 1-bits in a byte; a parity bit makes the total even (even parity) or odd (odd parity)Misses errors that keep the same parity (e.g. two bits flipped); cannot find which bit is wrong
Parity blockParity checked in rows and columns; the faulty row and column intersect at the wrong bitNeeds extra bytes; still weak against multiple errors
ChecksumValue calculated from a block by an agreed algorithm, sent with the block; receiver recalculates and comparesOnly shows that an error exists
Echo checkReceiver sends the data back; sender comparesUnreliable: cannot tell if the error was on the way there or back
ARQReceiver sends positive/negative acknowledgement; sender re-sends after a timeoutNeeds a two-way link

Parity bit

Example byte 1101100 (four 1-bits) with the parity bit at the left: even parity → 0 1101100; odd parity → 1 1101100. Sender and receiver must agree which type is used.

Check digits

A check digit is the last digit of a code, calculated from the other digits. It is a data entry check (not a transmission check) used for barcodes, ISBNs and VINs. It detects: an incorrect digit (5327 for 5307), transposition (5037), omitted or extra digits (537, 53107) and phonetic errors (13 for 30).

ISBN-13 method (with worked example)
  1. Add the odd-position digits (1st, 3rd, 5th …).
  2. Add the even-position digits and multiply by 3.
  3. Add the two totals and divide by 10.
  4. Remainder 0 → check digit 0; otherwise check digit = 10 − remainder.

Example 978034098382: odd sum = 9+8+3+0+8+8 = 36; even sum = 7+0+4+9+3+2 = 25, × 3 = 75; 111 ÷ 10 remainder 1; check digit = 10 − 1 = 9. To verify all 13 digits, the total must have remainder 0.

ISBN-13 tool (12 digits to generate, 13 to verify)

Modulo-11 method (with worked example)
  1. Weight each digit: for a 7-digit number use 8, 7, 6, 5, 4, 3, 2 from the left.
  2. Multiply each digit by its weight and add.
  3. Divide the total by 11.
  4. Check digit = 11 − remainder (written X if the result is 10).

Example 4156710: 32 + 7 + 30 + 30 + 28 + 3 + 0 = 130; 130 ÷ 11 = 11 remainder 9; check digit = 11 − 9 = 2, giving 41567102. To verify, weight the 8 digits 8 to 1: total 132, remainder 0, so it is correct.

Modulo-11 tool

Exam tips: parity detects but cannot correct (only a parity block can locate the bit); echo check is unreliable; check digits catch data entry mistakes, not transmission errors. If asked for steps, follow the algorithm printed in the question.

2.3 Symmetric and asymmetric encryption

Encryption scrambles data so that an eavesdropper (hacker) who intercepts it cannot understand it. It does not stop interception. Use it for sensitive data (bank details, medical and legal documents).

Symmetric encryption

The same key encrypts and decrypts. In the book’s simple example the 10-digit key 4291362856 shifts the letters by +4, +2, +9, +1 … and the key repeats. COMPUTER becomes GQVQXZGZ. Modern keys are 256-bit (2256 ≈ 1.2 × 1077 combinations). Main weakness: the key must be shared secretly, and it can be intercepted (the key distribution problem).

Extension: quantum cryptography

Uses the quantum properties of photons (polarised in two bases) to share keys securely (Quantum Key Distribution, BB84). Sender and receiver choose random bases and publicly compare which they used; only matching-basis results give a reliable 1 or 0. Not required for the exam.

Exam tips: use the terms plaintext and ciphertext; always state which key encrypts and which decrypts; say why asymmetric is more secure (the private key is never transmitted).
